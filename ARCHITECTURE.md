# Architecture

Product runtime constraints for `cadmcp`. This document is **not** an
internal agent playbook; it describes what any SolidWorks COM maintainer
must preserve.

Live tool counts, token budgets, and sequence totals live in
`docs/TOOL_INVENTORY.md` and the roadmap status card (generated by
`scripts/tool_inventory.py`) — this file does not hardcode those numbers.

## Backends

| Backend | Package | Role |
|---|---|---|
| Protocol / CAD-neutral | `cadmcp.backend.protocol` | Shared models, validators, `CADBackend` surface |
| Fake | `cadmcp.backend.fake` | Offline geometry engine for CI and local tests |
| SolidWorks | `cadmcp.backend.solidworks` | Real COM automation (Windows + SolidWorks 2025) |

`fake` and `solidworks` are peer implementations of the same protocol.
Feature packages must not depend on assembly packages across domains.
Business mixins must not import `backend.py` composition modules.

## Toolsets and profiles

Eleven toolsets are declared in `cadmcp.registry.TOOLSET_DEFS`, including
domain sets (`core`, `assembly`, `drawing`, `sheetmetal`, …) plus
`verification` (`verify_model`) and `transaction` (`tx_*`). Runtime
profiles (`full` / `part` / `assembly` / `drawing` / `sheetmetal`) select
closed toolset tuples via `TOOLSET_PROFILES` — do not move tools between
toolsets to “free budget”.

## STA (SolidWorks COM)

All SolidWorks COM work runs on a dedicated Single-Threaded Apartment (STA)
thread:

1. Every COM call goes through the STA executor.
2. Business mixins must not open their own COM connections.
3. COM objects must not be used from other threads.
4. COM objects must not be passed across threads.
5. COM init / attach / release / exception mapping stay on the STA lifecycle.
6. Thread start / stop / ready / error state remain explicit.
7. COM reference release is audited carefully.

Business mixins call COM only via `infrastructure.py`, which is the sole
business-side facade over `sta.py`. `sta.py` must not depend upward on
`infrastructure.py`.

After a working session, disconnect maps to `COM_LOST`; `reattach()`
recovers the COM link without auto-reopening documents. The executor may
retry at most once when safe (read-only, or mutating with no side effect
yet).

## Document context guards

Mutating tools accept optional `expect_title` / `expect_path`. The kernel
validates them after schema checks and before journaling / fingerprints /
handlers; mismatch returns `WRONG_DOCUMENT` with no side effects.
`list_open_documents` enumerates open docs with `DocInfo` (including
configuration / epoch / saved fields).

## Transactions

`transaction` tools implement a compensation-style checkpoint (L1: SaveAsCopy
+ journal under `.cadmcp/tx/`). L2 modes (`reload` / `compensate` / `discard`)
exist in the API; undo is intentionally not used. The L2 paths are marked
pending a real-SolidWorks re-run.

## Layering

```text
toolsets / kernel / executor
        ↓
backend protocol models
        ↓
fake  ⊥  solidworks
              ↓
     infrastructure → sta
```

- `naming.py` owns feature-name alias state.
- Sketch lifecycle state lives in the sketch modules.
- Error codes for COM failures are mapped in `sta.py` only.
- Catalog remediation (`auto` / `action` / `requires_confirmation`) feeds
  `cadmcp://help/errors` without changing the OpResult / ErrorInfo envelope.

## Gates (offline)

- `scripts/token_report.py --strict`: per-toolset tier budgets (large/small)
  with ≥20% unused headroom, profile caps, and TOTAL ceiling.
- `scripts/tool_inventory.py --check`: inventory + roadmap status-card drift.
- `scripts/bench.py`: Fake numeric fingerprint regression vs
  `benchmarks/baseline.json`.
- `scripts/check_release.py`: version literals (internal; not public-exported).

## Public API stability

Do not casually rename public tools, change default arguments, reorder COM
API sequences, or alter OpResult / error envelopes. Compatibility shims for
the pre-rename package name were removed; see [docs/naming.md](docs/naming.md).

## Skills and resources

Usage-layer skills ship as markdown under
`cadmcp/resources/content/skills/` and are exposed as `cadmcp://skill/...`
resources (same source as `help` topics under `cadmcp://help/...`).
